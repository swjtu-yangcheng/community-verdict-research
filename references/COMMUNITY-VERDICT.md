# COMMUNITY-VERDICT.md — "某群体实际用什么/喜欢什么"类调研方法论

适用问题形态：某类人群（士兵、医生、程序员、飞行员…）实际佩戴/使用/推荐什么产品。
这类问题的正确证据不是商业榜单，而是**当事人的第一人称陈述**。本文档规定该类任务的证据采集与判定规则。

## 1. 证据源优先级（覆盖通用 Evidence tiers）

| 层 | 源类型 | 采信规则 |
|---|---|---|
| P1 | **具名个人**：回忆录/自传/采访中白纸黑字写到自己用什么（如 Chris Kyle《American Sniper》写明戴 DW-6600） | 单人即可立论，标注"个例" |
| P2 | **可核实的照片**：官方新闻照片图注（DoD/厂商新闻图）、有明确人物与时间的实拍 | 单位级结论需 ≥2 张独立照片 |
| P3 | **当事人论坛原帖**：Reddit/专业论坛第一人称讨论，**必须给 permalink + 日期 + 引用原句** | 反映"真实选择"，但必须标注社区构成偏差（如 r/gshock 天然偏 G-Shock） |
| P4 | 二手整理（收藏类博客、垂直媒体深度文） | 可引用，但需回溯到 P1-P3 才算实锤 |
| D | **商业榜单/联盟营销文** | 仅作线索，禁止作为任何结论的唯一依据 |

## 2. 联盟营销/SEO 农场识别信号（命中即降为 D 层）

- 标题形态："Best X for 2026 (Ranked/Tested)"、"10 Best … Reviewed & Ranked"
- 正文结构：每个条目带 "Check Price on Amazon" 及 affiliate disclosure
- 域名异常：`storage.googleapis.com/<随机串>/…`（SEO 镜像农场，各"榜单"页内容互抄）
- "Summarized by AI" 的评论区摘要、无作者署名
- 来源单一互链：多篇"榜单"引用同一批上游博客（独立源独立性测试失败）

**教训记录（2026-10 美军腕表调研）**：实际引用了 `storage.googleapis.com/mcdnqldbztpvqw/…` SEO 农场页与多家 affiliate 榜单，违反本 skill 既有 D 层规则。此类任务必须先用 P3 层（Reddit 原帖）打底，再向上溯源。

## 3. Reddit 挖掘标准动作

1. 检索式：`site:reddit.com/r/<sub> <关键词>`，至少覆盖 3 个不同性质子版（职业版 r/army、r/USMC；爱好者版 r/<product>；泛版 r/<category>）
2. 每帖记录：permalink、发帖/热评日期、引用原句、发帖者自称身份
3. **偏差标注**：爱好者版块的推荐分布不得当作总体人群分布
4. 注意捡漏反向证据：与主流叙事矛盾的个体陈述（如"便宜货 F-91W 同样大量出现"）
5. 多引擎交叉：Reddit 帖常不被默认 WebSearch 排到前列，用 `site:reddit.com` 限定 + 多查询词族，必要时 Bash+curl 抓 old.reddit.com / JSON API（`https://www.reddit.com/r/<sub>/search.json?q=…&restrict_sr=1`）

## 4. 渠道三分法（涉及"配发/采购/自购"必用）

涉及"统一配发还是自购"的结论，必须拆成三个独立判据，不得混写：

- **个人自购**：当事人第一人称自述（"我入伍时自己买的…"）
- **单位配发**：需要供应链证据（训练补给清单、NSN 采购单、图注明示 issued）
- **政府采购资格**：有 NSN/GSA 编号 ≠ 大规模配发，两者必须显式区分

## 5. 时间分层

- **历史层**（如 GWOT 时代战地口碑）：标注年代与已停产状态
- **现役层**（2025-2026 当前在售型号/当前政策）：给出当前 SKU 与现行规定
- 结论中每条判断注明属于哪一层；禁止拿停产传奇款回答"现在他们戴什么"

## 6. 输出契约（在此类任务中强制追加）

在通用 Output contract 之上追加：

1. **置信度表**：逐条判断 × 结论 × 证据把握（高/中/低）× 主要证据层
2. **渠道归属**：每条"某群体用 X"结论标注 自购/配发/采购资格
3. **偏差声明**：列出所用社区源的构成偏差与商业源的利益关联
4. **统计可能性声明**：凡无系统性佩戴/使用统计的主题，显式写明"定性判断，非普及率排名"
